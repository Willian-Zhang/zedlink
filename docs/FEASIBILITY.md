# Native Zed feasibility

## Pinned source and scope

On 2026-10-03, the installed `zed --version` reported Zed 1.22.0 at commit `76659a55a8c10ed355a070f8764a0b1733e3c115`. The public Zed repository was fetched at that exact commit into the ignored, nested `zed-source/` checkout. `git -C zed-source rev-parse HEAD` matches it and `git -C zed-source status --short` was clean before implementation. The checkout's `AGENTS.md` was read. Its README reports source primarily under GPL-3.0-or-later, with components marked Apache-2.0; the checkout includes both license files.

This source inspection led to an opt-in Unix socket probe in `crates/agent_ui/src/zedlink_probe.rs`. It compiled with `cargo check -p agent_ui --offline`, built into the Zed binary, snapshotted a desktop-created native Agent thread, and sent a harmless prompt into that same thread through `ThreadView`. The checkout is a sparse working tree at a pinned base commit; local changes are uncommitted and must not be confused with the upstream revision.

## Packaging decision

The preferred stock extension is not feasible with this pinned extension API. The **minimal opt-in source addition** near `agent_ui` offers `/remote-control` in the native Agent composer, defaults to zero exposed threads per process, and toggles one eligible thread's exposure through the local command path. It dispatches text prompts through `ThreadView::send_content` when idle with no queued messages or `ThreadView::add_to_queue` when busy or queued. It rejects a send while desktop message contents are loading. A future installable extension would need a new supported API to register this native local command and access its selected thread. The patched Zed build, slash-command activation/revocation, local same-thread prompt/snapshot, and bounded event polling are verified. A private TLS gateway passed a transport fixture and a narrower real-Zed identity check; gateway same-thread execution and the mobile path are not verified.

The source has three relevant identities that must remain separate: process instance ID (new per launch), `acp::SessionId` for the persisted native conversation, and ZedLink event epoch (new per adapter restart). `AgentPanel` also has a UI `ThreadId`; it is not interchangeable with `acp::SessionId`.

## Build and proof gate

The pinned `docs/src/development/linux.md` documents `cargo run` and `cargo test --workspace`; `rust-toolchain.toml` pins Rust 1.98.1. `RUSTUP_TOOLCHAIN=stable cargo metadata --offline --no-deps --format-version 1` succeeds after materializing the workspace. `cargo check -p agent` and `cargo check -p agent_ui` passed. After installing missing Linux development headers and allowing Zed's pinned WebRTC archive download, `RUSTUP_TOOLCHAIN=stable cargo build -p zed --offline` passed for the current patch. An isolated patched Zed process listed and snapshotted a native thread after a desktop prompt, then accepted a local probe prompt through its `ThreadView`; the snapshot showed one matching user entry and an assistant entry with status `Idle`. Same-ID retry did not create a second user entry; changed text returned `REQUEST_CONFLICT`, and stale epoch returned `INSTANCE_UNAVAILABLE`.

Next, establish an authoritative request-to-native-turn link, authenticated event streaming, and the permission/cancellation paths. The local probe's send result is deliberately `unknown` for an idle thread because `send_content` schedules an asynchronous task; a snapshot can show the turn afterward, but the probe cannot yet prove acceptance at response time. Its event feed is bounded and polled, with no durable replay or phone transport. The first active cancel attempt reached `ThreadView::cancel_generation` but did not stop visible text updates before the wrapper became idle. A source guard now checks the initiating ACP turn ID before forwarding each native event; one subsequent live test showed visible text and event sequence stabilizing shortly after cancellation. Provider-side cancellation and broader race coverage remain unverified. The checkout's `AGENTS.md` README review notice was added before source edits and must remain for human review.
